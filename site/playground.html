Playground

Change the robot and watch what it does. Three labs, because a web page can run the geometry live but not the physics engine: a kinematic lab (live, in your browser), a physics lab (stored MuJoCo runs), and live physics that runs on your own machine.

What this lab is, and is not. It runs the project's own maths in your browser (closed-form inverse kinematics, the trot, crawl and pace foot paths, static joint torques) and checks them every time the page's code changes against the Python (tests/website/test_site_js.py). It is geometry plus gravity held still at each instant: no dynamics, no friction, no leg mass, no servo lag. The torque shown is what the servos would need to hold the weight in that pose, with the weight shared over the grounded feet by an assumption (see below). For real behaviour, use the Physics lab.

How these numbers are worked out, and what to distrust
  • Foot positions come from the gait generator: a grounded foot stays fixed in the world, a swinging foot lifts and moves to where its next stance starts. The legs follow by closed-form inverse kinematics; the trained network is not used here (it agrees with the closed form to a median 0.17 mm, see Results).
  • Weight sharing. Three feet down: the loads that balance the weight are unique. Two feet: the centre of mass is projected on to the line between them. Four feet: the balance is redundant, so the page takes the smallest loads that balance it, dropping any foot that would pull. MuJoCo shows the real split is not even (about 24% / 26% front / rear for a light-legged robot), so treat four-foot torques as an estimate of the order of magnitude.
  • Body centre = centre of mass, and the legs weigh nothing. The Physics lab has the real masses.
  • Torque is |Jᵀ F| for the vertical foot force F, in each leg's frame. Stall torque is the listed (unverified) 19 kg·cm at 5 V and 21.5 kg·cm at 6.8 V, on a straight line between.
  • "Heaviest robot" scales the current mass until the worst torque in the cycle is half the stall torque (an assumed continuous rating). It is an upper bound from weight alone, like torque_envelope.py.
  • Nothing here says the robot balances while moving: the trot has two feet down, so the body centre is never inside a support polygon, and that needs dynamics.
What this lab is, and is not. Every combination offered here was run once in MuJoCo (this project's physics model with the servo model: 20 ms latency, command steps of the real PWM driver, torque limits that depend on speed) and the motion was recorded. The page replays the stored run. There is no interpolation between combinations and each is a single run with no randomness, so the differences you see between neighbouring cells are real for the model but not a statistical result. Dimensions (50/150/150 mm legs, 300×150 mm body), masses, friction and servo figures are placeholders. To try other values, run scripts/gait/live_gait.py or scripts/gait/try_gait.py on your machine.

This tab needs the local server. Real-time MuJoCo physics with any robot dimension, gait or servo setting cannot run in a web page, so it runs in Python on your computer and this page only draws it. Nothing is sent anywhere: the server listens on 127.0.0.1 only and refuses other hosts and origins.
